# Learnings — PR #42671 review

- `validate-recipe.js` requires both a top-level `title` *and* `name`; `is_true` is not a known assert operator (use `eq: true`). Cheaper to dry-run early than discover during the live attempt.
- HUD warning `page.evaluate: Execution context was destroyed, most likely because of a navigation` reliably fires during the `perps/full-trade-lifecycle` recipe's testnet toggle + reload sequence. Treat as baseline-only when every AC node still has a PASS trace entry — matches the CLAUDE.local.md guidance verbatim.
- The auto-review JSON for the perps smoke flags ~17 events but all are repeat baseline noise: selector memoization, "Unknown action Object" Sentry envelopes, React Router v7 future-flag warning, MaxListenersExceededWarning. Don't surface these as PR-specific findings without a concrete tie to the diff.
- The Perps deposit toast lifecycle is driven by two derived bits of state: `selectPerpsShouldShowDepositToast` (eligibility — type-gated) and `selectPerpsDepositPending` (pending-window status set). After this PR, both are gated *only* by `TransactionType.perpsDeposit` / `TransactionType.perpsDepositAndOrder` + `lastDepositTransactionId` match — no payment-token check. Mobile equivalent (`app/components/UI/Perps/hooks/usePerpsDepositStatus.ts`) does the same on `transactionMeta.type` alone.
- `clearDepositResult` in `@metamask/perps-controller` (`PerpsController.cjs:1255-1259`) clears only `lastDepositResult` — *not* `lastDepositTransactionId`. Worth remembering for any future Perps-deposit lifecycle bugs: the txn id can outlive its result.
- The Perps deposit toast `useEffect` split (completion vs. pending in the same component) creates a narrow race window: if a new deposit fires before the 5s completion timer elapses, the pending effect's `hasDepositResult` early-return hides the new pending toast. Mobile sidesteps via a ref + balance watch. Useful pattern hint for future "missing toast" reports in this area.
- `domains/perps/recipes/full-trade-lifecycle.json` is a solid 14s baseline smoke for any Perps UI-touching PR — covers open ETH long, close ETH long, BTC market nav, network toggle, perps home. Cheaper than building a bespoke recipe when the change isn't visually testable.
- Live mainnet Perps slots cannot drive real deposits for review without committing funds. `Recipe decision: skip-funds-risk` is the correct standard-tier outcome for deposit/withdrawal UI PRs; rely on jest behavior tests + selector tests + the smoke baseline instead.
- `mockState.metamask` carries baseline perps fields; tests rely on explicit `transactions`, `lastDepositTransactionId`, `lastDepositResult` overrides to set the actual selector inputs. Always override all three when writing selector/toast tests.
- `transactionData[txId]?.paymentToken` is no longer consumed by either Perps deposit selector. Reviewers shouldn't add concerns about `transactionData` shape when the diff only touches these selectors — the slice is dead-path here.
