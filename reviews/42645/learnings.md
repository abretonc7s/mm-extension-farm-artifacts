# Learnings — PR #42645 (perps forced-trade badges)

- **CDP can drop mid-run on the standard slot.** Status check at step 4 succeeded (`Connected Chrome/147.0.7727.15`, wallet UNLOCKED) but by step 11 the port was refusing connections and `chrome-profile-pw` was gone from disk. The worker has no clean way to recover — `reopen-browser.sh` requires the profile, and `prepare-slot.sh` runs a long build (timed out at 240s with `app-init.js not found`). For standard tier, accept the fallback fast instead of fighting recovery.
- **Live evidence for forced-trade fills (TP/SL/Liq/ADL) is hard to manufacture in a slot.** The test account has live history but only standard fills. Real injection paths exist (`globalThis.stateHooks.getPerpsStreamManager().fills.pushData([...])` flows through `transformFillsToTransactions`, which sets `fillType` from `detailedOrderType` / `direction` / `liquidation`), but require crafting a complete `OrderFill` shape (see `node_modules/@metamask/perps-controller/dist/types/index.d.mts:541`). Useful next time if a fixture utility can be wrapped around it.
- **`transformFillsToTransactions` is the routing point for FillType.** Triggers: `direction === 'Auto-Deleveraging'` → ADL; `liquidation` truthy → Liquidation; `detailedOrderType` contains 'Take Profit' / 'Stop' → TP/SL. Knowing this would let a future recipe inject minimal-shape fills.
- **`isEqualCaseInsensitive` defensive layers are an antipattern in this codebase.** The util already returns `false` for non-string inputs, so callers don't need `!== null && !== undefined` guards. Worth a quick grep on next perps review to flag similar redundant patterns.
- **Mobile and extension perps trees often duplicate constants.** `PERPS_EVENT_PROPERTY` / `PERPS_EVENT_VALUE` exist both in `@metamask/perps-controller` (used by mobile) and `shared/constants/perps-events.ts` (used by extension). When reviewing perps PRs, sanity-check key names line up across both sides before flagging a mismatch.
- **Mobile-extension parity is not strict equality.** This PR's case-insensitive Liquidated check is more correct than mobile's `===`. Don't reflexively mark "diverges from mobile" as a finding — sometimes the extension fixes a bug mobile has.
- **Geositta's CHANGES_REQUESTED on this PR was content-bearing.** A nested `<button>` inside a row `ButtonBase` is invalid HTML; the fix (split row action from badge action via sibling layout in `transaction-card.tsx:193-215`) and the new accessibility test (`does not nest the ADL button inside another button when row is clickable`) are both worth noting as a pattern for future activity-row badges.
- **en_GB locale mirrors en in this repo intentionally.** Commit `39c2c24c` is explicitly `chore(perps): sync en_GB locale with new perps keys`. Don't flag the identical diff as a copy-paste error.
- **Unit-test depth on this PR is exemplary.** 10 cases in `perps-fill-tag.test.tsx` cover every FillType + negative paths + case-insensitive match. The `transaction-card.test.tsx` `ADL badge accessibility` describe block uses a DOM-ancestor walk to assert no nested buttons — a pattern worth reusing for future row-with-badge components.
- **`yarn lint:tsc` baseline is clean on this PR.** No baseline perps balance typing failures (`availableToTradeBalance` / `getTradeableBalance`) appeared, so diff-gating wasn't needed. Worth a quick re-check on every perps PR before commenting on TS errors.
