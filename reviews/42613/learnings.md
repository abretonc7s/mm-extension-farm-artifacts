# Learnings — PR #42613 review (close-all-positions modal)

- `usePerpsMetamaskFeeDiscountBips` issues `rewardsGetPerpsDiscountForAccount` via `submitRequestToBackground` on every mount and on account/chain change — never call it from a component that the parent always mounts. Either gate the mount in the parent (`{isOpen && <Modal />}`) or accept `isOpen` and short-circuit. Watch this whenever a perps modal that uses the discount hook is rendered by a tab/view that's always live.
- `test/jest/console-baseline-unit.json` is a CI gate; even when jest tests "pass", a baseline regression (e.g. +9 act warnings) is a real blocker. Always grep `tail -30 jest-out.log` for "Console Baseline Report" before declaring a green run.
- `perpsCalculateFees` is the canonical RPC for per-symbol rates. `FeeCalculationResult` exposes `feeRate`, `protocolFeeRate`, `metamaskFeeRate`, `feeAmount`. Callers that only want a rate can pass `{ orderType, isMaker, symbol }` without `amount`; the provider returns rates with no amount-dependent math.
- `PERPS_FALLBACK_FEE_RATES` lives in `shared/constants/perps.ts` (this PR moves it from `usePerpsOrderFees.ts`). Treat that as the SSOT for the 0.00045 / 0.001 / 0.00145 triple — both `usePerpsOrderFees` and `CloseAllPositionsModal` now consume it. Mirror that pattern instead of redefining locally.
- HyperLiquid's `marginUsed` already includes accumulated PnL. Don't add `unrealizedPnl` separately when computing "you'll receive" — it double-counts. The modal documents this; remember to question any future code that re-adds PnL to margin.
- `perps-view.test.tsx` mocks `./close-position` to bypass the real modal — when reviewing tests that exercise PerpsView interactions, check `jest.mock('./close-position', ...)` block before claiming a behavioural assertion has been proven end-to-end.
- For perps modal review under standard tier with CDP offline: jest + console-baseline + diff-read is enough to surface real regressions; don't gate review on screenshots when the act-warning baseline already encodes the symptom of the runtime concern.
- `usePerpsEventTracking` has dual signatures (`{ track }` and declarative `{ eventName, conditions, properties }`); both are called from `perps-view.tsx`. When reading a perps view, expect both call shapes in the same file.
- Modal cancel via overlay click intentionally fires `CLOSE_ALL_CANCELLED` — confirm with PM if telemetry is supposed to distinguish "dismissed by overlay" vs "cancel button" before treating that as a bug.
- `feeRequestId` ref + match-guard is the local pattern for cancelling stale fee fetches — mirror this whenever a perps modal computes derived fees from a streaming positions array.
