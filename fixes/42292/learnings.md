# Learnings — TAT-3075

- Bug was a single-line stub: `shouldDisplayOrderInMarketDetailsOrders = () => true`. Investigation went fast because the page comment "full-position TP/SL also appear in this Orders list" was a dead giveaway — grepping the comment landed directly on the predicate. Mobile alignment confirmed the intended behavior in two file reads.
- Time sink: the Playwright Chromium relaunched (mid-task `reopen-slot-browser` ran with the wrong slot id during recovery), spun up a fresh extension id with `ERR_FILE_NOT_FOUND` on `home.html`, and `soft-refresh-slot.sh --slot mme-5` failed because the actual slot id was `macwork-mme-5`. Killing the stuck Chromium PID + re-running `reopen-browser.sh --slot-id macwork-mme-5` fixed it. Worth documenting the slot-id-prefix gotcha in the worker template.
- Recipe-side gotcha: the perps market detail page renders inside a fixed-height container, so `window.scrollTo(0, document.body.scrollHeight)` does nothing — needed `parentElement` walking + setting `scrollTop` on the actual scroll container. Without that, AC1's "below the fold" auto-close screenshot looked WEAK.
- `stateHooks.getPerpsStreamManager().positions.pushData(...)` / `.orders.pushData(...)` is the cheapest way to validate market-detail orders/auto-close behavior end-to-end without spending real funds. The auto-close section reads `position.takeProfitPrice` / `position.stopLossPrice` directly, so simulating positionTPSL is just a single push.
