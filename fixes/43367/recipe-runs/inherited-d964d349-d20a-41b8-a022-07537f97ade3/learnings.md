# Learnings — TAT-3131

- **Investigation >> fix.** The fix is one line (`useConfirmActions.ts` push → `{ replace: true }`), but finding it required tracing the full deposit round-trip across four files (`usePerpsDepositConfirmation` entry, `wallet-initiated-header` back button, `useConfirmActions.onCancel`, `confirm/index.tsx` auto-exit) to see the push/replace asymmetry. The phantom-history mental model is the key insight; the diff hides how subtle it is.
- **Two infra blocks ate most of the time.** (1) The Add Funds deposit confirmation can't open in-slot — `perpsDepositWithConfirmation` rejects with `Invalid chain ID "0xa4b1"` (Arbitrum absent; only `0x1` configured). (2) The recipe runner's per-run validation browser had a broken Playwright Chromium cache (`temp/recipe/runtime/validation-7666/ms-playwright/chromium-1217` empty, re-downloading 165MB each run and never finishing). **Unblock for #2:** seed that dir from the working global cache `~/Library/Caches/ms-playwright/chromium-1217` (`cp -R …/.`); the runner then skips the download and runs. Worth baking into slot preflight.
- **Bash stdout mangles some source tokens** (showed `goBackTo`/`ARBITRUM` as `n`/`ln`). Trust the Read tool for source ground truth; don't trust grep-printed source text. Cost ~10 min chasing a phantom `n`-vs-`goBackTo` discrepancy.
- **Recipe runner reuses/launches its OWN browser on 7666** and replaces the slot browser; `--launch-existing-dist` forces a fresh validation browser. Don't keep direct-CDP probing the slot browser and expect the runner to attach to it. The slot browser dies during runner use; the orchestrator relaunches it.
- **Right proof for a nav-logic bug = unit test, not the recipe.** Since the e2e trigger (deposit) was infra-blocked and AC4 is build-agnostic, the revert-sensitive proof is the `useConfirmActions` test (fails on push, passes on replace). The recipe is a useful regression guard for the `navigate(-1)` mechanism, but it cannot prove this particular fix.
