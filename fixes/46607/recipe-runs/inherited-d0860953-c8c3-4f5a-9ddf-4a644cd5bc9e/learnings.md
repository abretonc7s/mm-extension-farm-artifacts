- Most of the time went into the runtime, not the fix. Analytics proof needs `SEGMENT_HOST` and a non-empty `SEGMENT_WRITE_KEY` in `.metamaskrc` plus a rebuild. `launch --build` refreshed `runtime-dist`, but the live service worker kept running the old dev build (Segment key null), so the collector stayed empty. It's worth checking the SW source for the key before you debug consent.
- `chrome.runtime.reload()` from the SW got the unpacked extension disabled (disable_reasons bit 24) in the preserved profile, and `mm-harness launch` can't recover from that. Re-enabling via `chrome.management.setEnabled` on chrome://extensions fixed it.
- `metamask.analytics.set_consent` throws when `dataCollectionForMarketing` is undefined, even though the fixture is already opted in. I skipped it. `ui.navigate page: perps` expects `perps-home-page`, which this layout doesn't have. I pressed `account-overview__perps-tab` instead.
- The ticket bundles three asks, and two of them already shipped. The real gap was an extension-only `BUTTON_TYPE` alias in `shared/constants/perps-events.ts`. It would have been quicker to diff the extension's emitted keys against `@metamask/perps-controller`'s `PERPS_EVENT_PROPERTY` first.
